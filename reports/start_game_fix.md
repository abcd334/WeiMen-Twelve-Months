# v0.5 開局跳頁修正

## 重現與原因

在獨立測試行程預載 Git 版本 `b56eb12` 的 models、data_loader、narrative、game_engine，再執行新版 app.py，重現以下流程：

開始新遊戲 → 新建立的遊戲仍標為 0.4 → 新版提示 → 開始新版遊戲 → 返回首頁 → 開始新遊戲 → 再次顯示新版提示。

原因有兩個：新版介面可能仍呼叫長時間執行行程內的舊版模組；提示頁的按鈕只清除 session，沒有真的建立新局。先前的升級測試甚至把「回到首頁」當作預期，未驗證接下來能否進入第一月。

## 修正

- 新增 game_runtime.py，在介面綁定引擎函式前檢查版本；發現舊版時，依相依順序重新載入模型、資料、敘事、調查與引擎。版本相同的普通 rerun 不重載，不改動進行中的遊戲。
- 模型與引擎共用 GAME_VERSION，新局明確使用當前版本。
- 首頁與升級提示共用 start_new_game()。兩個入口都直接建立新局、進入第一月；升級時使用原種子，清除舊問卷與選項狀態，產生新的問卷 ID。
- 真正的舊局仍等玩家點選後才重開，不把舊情報轉成新版已查證證據。

## 驗證

- 相同的真實 v0.4 模組預載重現：修正後建立 0.5 新局，直接顯示調查與派遣，沒有升級提示循環。
- 新增隔離行程測試：快取的舊模組缺少新版欄位及 API，仍能刷新後開局、完成首次查印派遣、重跑畫面，以及從舊 session 直接開始新版。
- 新增普通 rerun 不重載測試，以及舊種子保留、舊問卷清理、首次進入與重跑仍停在第一月的檢查。
- 完整 `python -m pytest -q`：158 項通過，包含三條主線的 Streamlit 完整操作測試。

本次沒有更動事件、資源與推理數值，未重跑平衡模擬；原 v0.5 模擬報告保留。未手動啟動、重啟或部署服務。以上測試驗證的是本機修正與舊模組情境，不宣稱已檢查使用者瀏覽器當時的行程內容。
