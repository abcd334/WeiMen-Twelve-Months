# 危門 v0.7 · 山門歲月

小規模武俠門派模擬 × 動態人物歷史 × 事件回呼。

六名普通門人從同樣的「門人」身分開始。誰第一次獨立辦事、誰在失手後再獲機會、誰把負傷的同門背回來，會逐漸決定這局的重要人物。沒有預設主角，也沒有固定每月夜談。所有內容在本機執行，不使用 AI API。

## 啟動

```powershell
Set-Location 'C:\Data\GitHub\危門十二月\WeiMen-Twelve-Months'
& '.\.venv\Scripts\python.exe' -m streamlit run app.py --server.address 127.0.0.1
```

開啟 [本機遊戲](http://127.0.0.1:8501)。連接埠已使用時，可加 `--server.port 8502`。

其他電腦使用 Python 3.11 以上：

```powershell
py -3 -m venv .venv
& '.\.venv\Scripts\python.exe' -m pip install -r requirements.txt
& '.\.venv\Scripts\python.exe' -m streamlit run app.py --server.address 127.0.0.1
```

沒有新增執行期依賴。`requirements.lock.txt` 保留可重現環境。

## 怎麼玩

1. 每旬選一項主要安排：外勤、處理人物請求、休養、修煉、短工、建設或任命。
2. 指定參與者，第一位負責帶隊。一般一至兩人，主要休養最多六人；特定人物事件需要當事人參與。
3. 替其他門人安排休養、修煉、守山、藥圃或客舍工作。同旬不會重複派遣。
4. 確認後查看成果、資源、傷病與同門自行發生的互動，再進入下一旬。
5. 「門人與共同歷史」保留每人的經歷、關係、共享記憶與曾經被提起的往事；「山門記事」可回看每旬事件。
6. 完成 24 次決策後，回答「你最記得誰，因為發生過什麼？」。這只是第一段歷史的回看，遊戲可以繼續。

每月三旬，每年 36 旬。第十二月下旬進行歲末危機，守住山門就進入下一年。糧盡連續三旬、門人全數離開或歲末失守才會結束。

## 人物與回呼

- `Experience` 記錄個人經歷與來源；`SharedMemory` 記錄參與者、旬數、重要性、來源經歷與可用標記。救援另外保留救人者和被救者，避免把方向說反。
- 回呼只能讀取至少三旬前、參與者符合的真實記憶，並有冷卻與事件去重。同門關係再高，也不會憑空產生救援往事。
- 回呼會改變後續任務的合作效果，或影響信任事件與門派資源；人物頁也會標記哪些事後來又被提起。
- 人物依不同時期的多種經歷成為熟面孔、核心人物。重複同類經歷的敘事權重有上限；普通短工不會單靠反覆累積就成為核心人物。遊戲畫面不顯示權重或隱藏心理分數。
- 連續成功會增進相關能力；高風險外勤可形成「果決」，失手後重新成功可形成「穩重」。長期帶人、醫療或修煉會留下不同方向。
- 被忽略者會先提出要求，再表達離山意向，至少兩次較早旬的預警後才會離開。實際安排工作或回應要求可以挽留。

## 經營與職位

資源只有糧餉、防備、聲望；設施只有練武場、藥圃、客舍。每旬每兩名在門人員需約一份糧餉，山門另耗損一點防備。工作與出勤會增加疲勞；疲勞達 65 後工作收穫降低，也更難完成外勤。休養每旬減少 22 疲勞，傷勢每休養兩旬減輕一級。重傷不能派遣。

人物成為核心人物，並備妥二級設施與對應經歷後，可任命：

| 職位 | 經歷要求 | 留門時的功能 |
|---|---|---|
| 藥堂主事 | 藥圃工作至少 6 旬、醫術至少 4、二級藥圃 | 自動協助一名休養中的傷員換藥 |
| 外務領隊 | 參與任務至少 4 次、帶隊至少 3 次、二級客舍 | 帶一名留門修煉者處理普通送貨差事 |
| 教習 | 修煉至少 6 次、帶人至少 3 次、武力至少 4、二級練武場 | 自動指導一名留門修煉者 |

同一職位同時一人。休養、外勤、重傷或過度疲憊時暫停職務效果。

假名帖從二月開始，作為三段長期支線與普通事件並存；每段可調查、協商、賠付、請行會協助或暫不處理。每次處理後相隔四旬再有後續；一直未回應會損失聲望，但不會卡住時間。這局不需要管理證據板或封存核對流程。

## 存檔與升級

側欄或首頁的「本機存檔／讀檔」可下載與讀取 JSON。存檔包含種子和實際行動，以引擎重播恢復進度，並驗證結果摘要與亂數序列的可重現性。支援最多 1000 次決策、4 MB；格式或重播不符時保留目前進度。存檔使用相同修訂的 v0.7 規則，跨規則修訂不保證相容。

舊版連線需要按「開始新版遊戲」以原種子重開，舊四人案件進度不自動遷移。v0.6 程式留在 `app_v06.py` 與原有引擎模組，可另行執行；舊測試仍完整檢查該版本。

回看問卷保存於 `feedback/v07_responses.jsonl`，不會上傳。存檔和問卷不消耗遊戲亂數。

## 程式分工

| 檔案 | 責任 |
|---|---|
| `app.py` | v0.7 旬制安排、門人歷史、回看及存讀檔介面 |
| `sect_models.py` | 在既有 Character／GameState 基礎上新增歷史、共享記憶、敘事權重與旬制狀態 |
| `sect_content.py` | 六名門人、22 個一般事件、3 段支線、8 個條件事件／危機模板 |
| `sect_engine.py` | 派遣驗證、歷史回呼、人物階段、傷疲、分工、職位、自發互動與跨年 |
| `sect_save.py`、`sect_feedback.py` | 可驗證的 JSON 重播存檔與本機質性回饋 |
| `game_runtime.py` | 舊快取與同版本程式修訂的載入更新 |
| `review_sect.py` | 公開資訊策略模擬、記憶來源稽核、閱讀稿與重播驗證 |
| `app_v06.py`、原有引擎與 `tests/test_app.py` | v0.6 相容回歸；主遊戲不再走此流程 |
