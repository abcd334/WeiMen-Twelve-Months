# 危門十二月 v0.3

本機、單人、回合制武俠門派經營遊戲。依相鄰的 `危門十二月_v0.3_完整設計與開發指令.txt` 實作。你擔任青崖門代理掌門，與四名隨機弟子度過十二個月，最後面對烈川堂。

## Windows PowerShell 啟動

本工作區已準備 Python 3.12 虛擬環境，可直接執行：

```powershell
Set-Location 'C:\Data\GitHub\危門十二月\weimen_game'
& '.\.venv\Scripts\python.exe' -m streamlit run app.py
```

用瀏覽器開啟 <http://127.0.0.1:8501>。在啟動終端按 `Ctrl+C` 停止。若 8501 已被使用，可在指令後加上 `--server.port 8502`，再開啟相應網址。

複製到其他 Windows 電腦時，先安裝 Python 3.11 以上，於專案目錄執行：

```powershell
py -3 -m venv .venv
& '.\.venv\Scripts\python.exe' -m pip install -r requirements.txt
& '.\.venv\Scripts\python.exe' -m streamlit run app.py
```

若需要與本次驗證相同的套件版本，改用 `-r requirements.lock.txt`。不必啟用虛擬環境，因此無須調整 PowerShell 執行原則。開發機上使用的 `.tools/` 是專案內的 Python／uv 安裝輔助檔，不是遊戲內容，不應提交版本庫。

## 玩法

1. 輸入種子或使用隨機種子，開始新遊戲。相同版本、相同種子、相同行動會重現同一局。
2. 每月先處理延遲後果，再扣除 3 點糧餉。首月顯示的糧餉為 47，扣款前初始資源為 50／35／30。
3. 白天比較三個方案的成本、建議能力、人數、風險與背景提示，再挑選一至兩名弟子。確認前可以更換方案與人選。
4. 確認派遣後查看結果及觀察札記，再進入夜談；回應後查看反應，再進入下一月。
5. 重傷者必須留門休養。高疲勞、輕傷及同伴配合會影響任務。只有標示「致命風險」的派遣可能造成死亡。
6. 第十二月直接根據門派資源、可行動弟子能力、情報與盟友判定結局。結局後可看四名弟子的去向、人物心跡及因果回放。

遊戲沒有自由文字指令。夜談與問卷皆使用固定選項；種子是唯一數值輸入。沒有 AI API、遊戲網路服務、帳號、資料庫、裝備、建築、額外招募或部署功能。

## 內容與規則

- 四名弟子各以武力、智略、醫術、交涉之一為專長；姓名、背景、秘密、個性及外顯習慣由種子決定。每人至少有一名關係人物；每局保證主線相關秘密，但不保證有通敵者。
- 20 個門派事件：第 1／4／8／12 月固定主線，加上 16 個單局不重複的隨機事件。十二月決戰沒有一般派遣選項。
- 六套人物弧線：身分隱瞞、家族舊債、對失敗的恐懼、權力與認同、保護同門、敵派舊關係。夜談先呈現異常，再提出具體取捨；多次回應後產生結果敘述，個人終局於結局統一交代。
- 一般 UI 採公開欄位白名單，不會顯示心理數字、未發現秘密、精確成功率或結算前的資源結果。已觀察到的秘密片段可成為公開客觀經歷。
- 札記分為可核對事實（強線索）、言行觀察（弱線索）、日常片段（情境噪音）。離開與倒戈必須有至少兩個**較早月份**的相關警示，且至少一項為強線索。當月剛發出的警示不能用來立即允許永久後果。
- 任務同時考量能力、背景、傷疲、關係、情報與有上限的心理修正。雙人派遣由主力帶領，另一人提供支援；無法僅以單一心理值決定重大結果。
- 決策與後續事實以 ID 關聯；延遲效果會回寫到原決策。結局最多挑選八項決策，所有回放文字引用實際產生的事實，不補寫未觸發的支線。

結局依設計文件 A 部分的優先序：揭破陰謀 → 聯盟退敵 → 正面取勝 → 慘勝守山 → 門派覆滅。智略、交涉、武力合計只計入可行動弟子；人數條件則計算仍在門內者。十二月決戰不額外擲死亡判定。

## 測試與模擬

```powershell
& '.\.venv\Scripts\python.exe' -m pytest -q
& '.\.venv\Scripts\python.exe' simulate_balance.py --games-per-policy 250
```

模擬不載入 Streamlit。四種策略共 1,000 局，使用相同的 0～249 種子集合；策略的隨機選擇與遊戲亂數分離，兩者均由同一局種子導出，策略不偷看心理欄位或秘密。

- `random_policy`：先均勻抽合法方案，再抽合法人選，夜談隨機選擇。
- `highest_skill_policy`：依建議能力配人，並以傷疲作為同分取捨；夜談依公開性格與當前糧餉決定。
- `conservative_policy`：避開高風險、保留疲勞與武力／智略核心；夜談優先照顧疲勞者，否則維持規矩。
- `resource_guard_policy`：照顧最低資源，配合可見的成本與建議能力；門內資源緊繃時優先維持輪值。

完整結果：

- [四策略摘要](reports/balance_summary.md)：結局比例、平均資源、留門人數、重大人物後果及各結局的策略分布。
- [完整統計](reports/balance_report.json)：各事件選項的選取與成功次數、公平性樣本。
- [固定種子公平性稽核](reports/fairness_audit.json)：離開、倒戈、死亡各三例，記錄實際警示月份與文字。
- [驗證與設計假設](reports/verification.md)：測試、啟動檢查、數值觀察及限制。

## 檔案

| 檔案 | 用途 |
|---|---|
| `app.py` | Streamlit 首頁、人物卡、派遣、夜談、結局與側欄 |
| `models.py` | 單局／人物／線索模型、公開人物白名單 |
| `game_engine.py` | 人物生成、回合、任務、線索公平性、成長、結局與回放 |
| `data_loader.py` | JSON 載入與資料完整性驗證 |
| `data/character_templates.json` | 人物模板、相容規則、外顯特徵、線索文案 |
| `data/mission_events.json` | 主線、隨機事件、方案、效果、情報與公開旗標 |
| `data/personal_events.json` | 六套三階段人物弧線與有代價的回應 |
| `feedback.py` | 固定選項問卷與本機 JSONL 保存 |
| `simulate_balance.py` | 四種策略、整局模擬、重大後果稽核 |
| `tests/` | 生成／引擎／結局／Streamlit 整局操作測試 |
| `.streamlit/config.toml` | 本機監聽、簡單配色、停用使用統計傳送 |
| `requirements*.txt` | 必要套件與本次驗證版本 |

遊戲狀態僅存於 `st.session_state`，未實作跨連線存檔。正式問卷保存在 `feedback/responses.jsonl`，不進入遊戲亂數、不改變結局；同一份問卷重送不會重複新增。測試問卷寫入測試暫存目錄，不混入正式回饋。

## 實作假設

文件的「每月兩階段」與「十二月直接判定結局」採後者的明確規則：可操作月份為 1～11 月，第 12 月直接進入決戰。夜談優先挑本月出勤者，其次選出場較少者，故無法保證每人都有相同夜談次數；尚未深入的個人弧線會在個別結局如實標示。

全員都無法出勤、或沒有任何方案符合人數與成本時，提供「全員留門休整」以避免卡死，代價是防備與聲望流失。不會補充替代弟子。未出勤者在次月減輕傷疲，支援性夜談亦可花費藥糧休養。這些是將設計落實為可玩流程所需的明確規則。

問卷的「最記得的習慣」採四名弟子的習慣供回認，遵守不開放自由輸入的限制；因此只能衡量回認，不能當作無提示記憶力的證明。實際 20～40 分鐘遊玩長度、人物記憶與重玩意願仍待真人試玩。

介面狀態與自動化測試依 [Streamlit Session State](https://docs.streamlit.io/develop/api-reference/caching-and-state/st.session_state) 及 [AppTest](https://docs.streamlit.io/develop/api-reference/app-testing/st.testing.v1.apptest) 官方介面實作。
